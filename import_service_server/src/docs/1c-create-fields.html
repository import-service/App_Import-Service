Заявка из приложения → 1С: какие поля брать

Import Service. Источник данных: тело создания заявки (HTTP POST на URL create из админки). Не из файлов и не из state.

Сервер шлёт в 1С JSON после того, как клиент создал заявку и загрузил файлы. Ответ 1С на create: requestId, external1cId. Документация: https://157-22-173-7.sslip.io/docs/onec

1. Юрлицо (от кого пришла заявка)

Брать из анкеты create, не из сканов.

Поле JSONПримерСмысл
legalEntityNameООО ВекторНаименование ЮЛ / ИП / физлица-заявителя
legalInn7707083893ИНН, 10 или 12 цифр
inn7707083893Алиас, то же значение, что legalInn
legalEmailmail@example.comEmail организации
legalPhone+79990000000Телефон организации

Физлицо (владелец авто / на кого заявка) — отдельные поля:

Поле JSONПримерСмысл
individualFullNameИванов Иван ИвановичФИО
individualPhone+79991112233Телефон
individualSnils123-456-789 00СНИЛС

Если в карточке 1С юрлицо пустое — эти поля с create не разобраны.

2. Оповещение, что пришла новая заявка

Отдельного поля «уведоми менеджера» нет. Заявка уже приходит create’ом. Колокольчик / задача / почта менеджеру — логика 1С после успешного приёма create.

3. Марка и модель автомобиля

Поле JSONПримерСмысл
carMakeToyotaМарка
carModelCrownМодель
vinVIN12345678901234VIN

Тоже из create, не из файлов. Если в 1С пусто — поля не смаплены.

4. Ввоз авто за 12 месяцев и даты ввоза

В приложении галочки нет. Есть список дат. Пустой массив = не ввозили.

Поле JSONПримерСмысл
previousImportDates["2025-11-02", "2026-03-15"]Даты ввоза, формат YYYY-MM-DD
importedLast12MonthstrueСервер считает сам: true, если массив дат не пустой

Для пояснения в 1С использовать даты из previousImportDates, не только boolean.

5. Авто в собственности (название и год → в пояснение)

Галочки нет. Есть список. Пустой массив = других авто нет.

Поле JSONПримерСмысл
ownedVehiclesсм. JSON нижеМассив объектов: наименование + год выпуска
ownedVehicles[].nameToyota CamryМарка и модель
ownedVehicles[].year2018Год выпуска, число
ownsOtherCarstrueСервер считает сам: true, если список не пустой
{
  "ownedVehicles": [
    { "name": "Toyota Camry", "year": 2018 },
    { "name": "Hyundai Solaris", "year": 2020 }
  ]
}

В пояснение: по каждой строке name и year.

6. Клиент прикрепил не тот документ или плохое качество

Отдельного поля «брак паспорта» нет.

Что сделать в 1СКак клиент видит / что делает
Написать в чат заявкиСообщение в приложении
Или POST /api/integration/customs-requests/state с statusSubType = signature_revision_requiredПодсказка в МП (типично для брака подписи)
Клиент снова upload с тем же docType (например passport_front, inn)Файл на сервере перезаписывается, сервер отдаёт 1С update файлов

7. Готовые документы на подпись обратно в приложение

Недостаточно прикрепить файл только в карточке 1С. Нужен upload на сервер Import Service.

ШагКтоЧто
11СPOST /api/customs-requests/upload — оригинал, docType без суффикса (например contract, kuts, explanatory_note)
2СерверКладёт файл в заявку, пуш в МП
3Клиент в МПСкачивает оригинал, подписывает
4Клиент в МПUpload с docType + _sign: contract_sign, kuts_sign и т.д.

state файлов не содержит — только статус, менеджер, суммы. Файлы только через upload.

8. Общий чат организации (не из create)

Отдельная фича: один чат на организацию, не привязан к requestId / external1cId заявки. В МП — закреплённая строка «Общий чат». В архив заявок на физноситель не входит.

Ключ организации — id_1c (GUID из синхронизации POST /api/integration/organizations). Полная спецификация: https://157-22-173-7.sslip.io/docs/onec, WSS: /docs/wss1c.
Отличие от чата заявкиОбщий чатЧат заявки
Комната / ключorg:{organizationId}, query id_1cпо external1cId заявки
Unread в МПключ orgключ = requestId
Push в МПtype: new_org_messagenew_message по заявке

8.1. Как 1С получает сообщение клиента из МП

Сервер доставляет одним из двух путей (без дубля):

СпособКогдаЧто сделать в 1С
WSS Открыт сокет по организации Подключиться к
wss://157-22-173-7.sslip.io/ws/1c/org/?id_1c=GUID-ORG-1C&token=INTEGRATION_BEARER_TOKEN
После connect: chatKind: "org". Событие message_created — как у чата заявки.
HTTP Нет живого WSS 1С Опубликовать метод POST …/organization-chat на стороне 1С (URL от create-URL админки, суффикс /organization-chat, аналог /customs-request-chat).

Пока organization-chat в 1С не реализован, исходящие из МП могут оставаться со статусом failed — это ожидаемо.

{
  "id_1c": "GUID-ORG-1C",
  "organizationId": 14,
  "clientMessageId": "f14d9f58-f1c0-4f4d-b3ef-f92d0cc7077f",
  "text": "Вопрос по организации",
  "authorType": "app_user",
  "chatKind": "org",
  "attachments": []
}

8.2. Как 1С пишет клиенту в общий чат

СпособEndpointОбязательные поля
WSS send тот же /ws/1c/org/ текст или attachments[] с fileUrl
HTTP POST /api/integration/organization-messages id_1c, message1cId (дедуп), text или вложения
История HTTP GET /api/integration/organization-messages?id_1c=… —

Вложения с 1С: POST /api/integration/organization-messages/attachments (id_1c, JSON+fileBase64). Имена файлов: o{organizationId}_…. Раздача: GET /api/customs-requests/files/:storedName.

{
  "id_1c": "GUID-ORG-1C",
  "message1cId": "MSG-0001",
  "text": "Добрый день, ответ менеджера",
  "sender1cId": "GUID-MANAGER",
  "senderName": "Петров",
  "attachments": []
}

Auth для integration HTTP: Authorization: Bearer <INTEGRATION_BEARER_TOKEN>. Организация должна быть синхронизирована (organizations.id_1c).

9. Массовая рассылка всем клиентам

Одно сообщение — всем организациям с deleted_at IS NULL. Для каждой организации:

  • сообщение в общий чат (как от менеджера/рассылки);
  • push в приложение (new_org_message);
  • email на organizations.login (если похож на email).

Клиент может ответить в общем чате. Рассылка не архивируется отдельно — это обычные входящие в org-chat.

КтоМетодНазначение
1СPOST /api/integration/broadcastsТекст + опционально attachments[] или fileBase64
1СPOST /api/integration/broadcasts/attachmentsСначала загрузить файл → fileUrl, потом в attachments[]
АдминкаPOST /api/admin/broadcastsТот же эффект: multipart text, file
{
  "message1cId": "BROADCAST-2026-001",
  "text": "Уважаемые клиенты, напоминаем о графике работы.",
  "senderName": "Import Service",
  "attachments": [
    {
      "fileUrl": "/api/customs-requests/files/bc_….pdf",
      "fileName": "notice.pdf",
      "mimeType": "application/pdf"
    }

}

message1cId — id рассылки для дедупа (в чате каждой орг: broadcast-{message1cId}-org-{organizationId}). Файлы рассылки на диске: префикс bc_.
