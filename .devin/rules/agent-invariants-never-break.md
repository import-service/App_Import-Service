# Инварианты (не нарушать)

**Сначала** всегда `approve-before-any-action.md` (план + утверждение **до** любых тулов). Этот файл — дополнительные запреты.

Перед **ответом с действиями**, **кодом**, **деплоем**, **сборкой** — свериться с обоими.

## Запрещено без явной просьбы пользователя

| Действие | Только если пользователь написал |
|----------|----------------------------------|
| `flutter build apk` / `aab` / `ipa` / release / копирование в `D:\Temp` / bump версии «под релиз» | **Только** явные слова: «собери apk», «сделай aab», «ipa», «релиз для стора». **Не** подразумевать из «почини», «исправь», «чиним МП» |
| `git commit` / `git push` | «закоммить», «запушь», «commit», «пуш» |
| Деплой на прод (scp, pm2, миграции) | «задеплой», «на прод» — **кроме** обязательного деплоя после правок server по `server-deploy-vps.md` |

**Release-сборки — никогда «заодно».** Фикс кода ≠ сборка APK. Сначала `flutter run` / проверка пользователем. APK/AAB/IPA **только** по прямой команде в **этом** сообщении.

## Делает агент, не пользователь

- Setup: `pub get`, `dart analyze`, `flutter analyze`, load-check server
- Деплой server после правок API — агент сам (`deploy-server-vps.ps1`)
- Не писать «выполни у себя», «скопируй в .env»
- См. `agent-does-setup-never-user-chores.md`

## Продуктовый цикл

- **Сначала** `approve-before-any-action.md`: разъяснить → план → «Утверждаешь?» → только потом тулы/код.
- Затем `feature-delivery-workflow.md` для фич.
- Без утверждения — не код, не SSH, не «проверка на проде».

## После правок кода

- `app/` / `admin/` → `flutter analyze` или `dart analyze` (0 errors)
- `server/` → load-check изменённых модулей
- См. `mandatory-verify-after-code-changes.md`

## Концепция заявок

Любая задача по заявкам, статусам, docType — сначала `project-concept.md` + `docs/request-lifecycle.md`.
