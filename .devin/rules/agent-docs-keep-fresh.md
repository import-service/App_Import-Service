# Агентские доки всегда свежие

**Не путать** с HTML на сайте (`api.html` / `/docs`) — там только контракт для людей/1С (`docs-for-humans-is-html.md`).

Этот файл — про **документы для агента**: `.devin/rules/*.md`, `import_service_app/.devin/rules/*`, при необходимости краткий канон в `docs/*.md`.

## Когда обновлять (обязательно)

После реализации **любой** фичи или заметного UI/флоу — **в том же подэтапе**, до «готово»:

| Изменение | Куда писать |
|-----------|-------------|
| Роли, экраны shell, навигация, вход | `app-runtime-architecture.md` (§ авторизация / роли) |
| Новый экран / виджет / хелпер | `app-context-map.md` (реестр) |
| Флоу заявки, upload, статусы, docType | `docs/request-lifecycle.md` + при смене смысла платформы `project-concept.md` |
| Ловушка / регрессия | `pitfalls-and-regression-guards.md` |
| Админка / сервер флоу | соответствующие `*.md` в admin/server |

Даже «только UI» (кнопка, кэш, профиль, QR) — **короткий абзац** в runtime/map, чтобы следующий агент не гадал по коду.

## Как писать

- Кратко: роль → экран → ключевые файлы → инвариант («не ломать»).
- Не копировать весь код; не дублировать HTML API.
- Если фича затрагивает и API — отдельно обновить `api.html` (люди) **и** agent docs.

## Запрещено

- Закрывать фичу только кодом, без апдейта agent docs, когда появился новый флоу/роль/экран.
- Считать «архитектура = только обмен с 1С» — карта **функций МП** тоже канон.

## Чеклист в конце подэтапа

1. Код + verify (`mandatory-verify-after-code-changes`).
2. Agent docs обновлены под новое поведение.
3. В ответе пользователю — одной фразой, что доки агента синхронизированы (если трогали).
