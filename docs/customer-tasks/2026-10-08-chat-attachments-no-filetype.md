## Цитата заказчика (дословно)

> Добрый день!  
> Приложение:  
> при отправке документов в чате (с приложения в 1с и с 1с в приложение) - отправить могу, в чате в 1с (и в приложении) появляется, а загрузить не могу - **не прописывает тип файла**

## Скрины

1. **1С:** «Ошибка получения файла с сервера.»
2. **1С:** «Сохранение файла» — имя без расширения, «Тип файла» пустой.
3. **МП:** имена с `.jpg`/`.pdf`, баннер «Не удалось открыть документ».

## Понимание (1:1)

1. Отправка вложений в обе стороны работает; в чате видно.
2. Скачать/открыть нельзя и в 1С, и в МП.
3. Формулировка Ксении про «тип файла» = симптом в UI 1С; в МП — отдельный fail открытия.

## Промежуточный итог проверки (2026-10-08)

### БД / диск / GET (request 62)

| Файл | Направление | `fileName` / `mimeType` в БД | На диске | GET JWT org25 | GET 1С Bearer |
|------|-------------|------------------------------|----------|---------------|---------------|
| `IMG-….jpg` | МП→1С | `.jpg` / `image/jpeg` | ok (`chat-attachments`) | 200 jpeg | 200 jpeg |
| `Расписание….pdf` | МП→1С | `.pdf` / `application/pdf` | ok | 200 pdf | 200 pdf |
| `ПТД Тест1.PDF` | 1С→МП | `.PDF` / `application/pdf` | ok | 200 pdf | 200 pdf |

Исключено: «файла нет на сервере», «mime не записан в attachments».

`Content-Disposition` сервер **не** отдаёт (ни для МП, ни для 1С).

### Причина МП (подтверждено кодом)

`resolveApiAbsoluteUrl` / `_resolveFileUrl`:

- base = `https://app.import-service.su/api/`
- `fileUrl` чата = `/api/customs-requests/files/r62_….pdf`
- после `substring(1)` + `Uri.resolve` → **`https://app.import-service.su/api/api/customs-requests/files/…`** (двойной `/api`)

Проверено `dart run`: именно так. Download падает → «Не удалось открыть документ».

Почему документы заявки могут открываться: в DTO заявки `fileUrl` часто уже **абсолютный** `https://…` → resolve не ломает. В чате — **relative** `/api/…` → ломает.

### 1С (гипотеза, согласована с симптомом)

- Docs: в `HTTPЗапрос` — только path из `fileUrl`, хост в соединении; не склеивать `…/api` + `/api/…`.
- «Ошибка получения файла с сервера» = HTTP download fail (часто та же склейка → `/api/api/…` или без Bearer).
- Пустой «Тип файла» + имя без `.ext` в диалоге Windows: клиент 1С не подставляет `mimeType`/`fileName` с расширением; сервер не шлёт `Content-Disposition` с именем — усиливает симптом, но **не** объясняет ошибку получения alone.
