# 2026-10-26 — «Админ admin@gmail.com» в недавних входах + нет окна прогресса загрузки APK

**Статус:** done (код) — проверка на устройстве при следующем обновлении.

## Цитата заказчика (дословно)

> Николай, сейчас на телефоне обновлял приложение с сервера с 57 на 58
> Окна самой загрузки с прогрессом не было
> После скачивания, уведомление в шторке было
> Установил
>
> И еще у меня в числе заходов появился какой то Админ с почтой на gmail
> Это что такое?
> Я заходил только primsnab и manager

## Понимание

1. При обновлении 57→58 не было окна прогресса загрузки в приложении; была только системная нотификация по завершении.
2. В «Недавние входы» на «Профиле» появилась запись `admin@gmail.com / Админ`, которую заказчик не создавал.

## Уже проверено (код)

- `admin@gmail.com` — **наш QA-сид** (`lib/core/auth/qa_known_accounts.dart`), безусловно подмешивался в `RecentAccountsService.list()` на всех устройствах (`_mergeQaSeeds`), включая запись в secure storage. Не взлом, не чужой вход — наша тестовая учётка.
- Диалог прогресса загрузки APK в приложении есть с v1.0.40 (`AppUpdateService.installFromServer`) — но **только в server-flavor**. В store-flavor (`AppDistribution.isStore`, без `REQUEST_INSTALL_PACKAGES`) «обновить с сервера» открывает ссылку в браузере → качал Chrome → уведомление в шторке. Скрин заказчика: RuStore 1.0.57 — вероятно стояла сторовская сборка.

## Сделано

- QA-сиды (`admin@gmail.com`) теперь подмешиваются **только в debug-сборках** (`kDebugMode`).
- В release `list()` дополнительно **вычищает** уже записанные сид-записи из secure storage — у заказчика «Админ» пропадёт после обновления до 1.0.59+.

## Как проверить

1. Где: «Профиль» → «Недавние входы» (релизная сборка 1.0.59+).
   Ожидание: нет `admin@gmail.com / Админ`; остаются только реальные входы.
   Провал: запись «Админ» видна в release.
2. Где: обновление с сервера на server-flavor сборке.
   Ожидание: диалог «Скачивание обновления» с процентами.
   Провал: нет диалога при скачивании в server-сборке.
