# 2026-11-16 — Тест5: комментарий в 1С на всех путях, подсказки/напоминания в МП

**Статус:** done — сервер задеплоен, проверки пройдены.

## Цитата заказчика (по смыслу)

> В комментарии заявки в 1С то есть «Повторный ввоз» и авто в собственности, то нет.
> Пустой слот подписи: вместо красного «Требуется подпись» — «Загрузить».
> «Передайте оригиналы» показывается и при полностью сданных оригиналах.
> Блок оплаты горит красным, хотя чек загружен.
> «На подпись» не пропадает сразу после загрузки и возвращается после обновления.
> На Android статусы приходят с задержкой 1–2 минуты, на iPhone быстро.
> ИНН/телефон физлица доходят до заявки, проверить, не теряются ли до 1С.

## Факты (проверено кодом)

- `enrichCommentTextForOneC` применялся только в `buildCreatePayloadFromBody`; живой путь (`uploadBatchSync` → `submitCustomsRequestTo1CFromDb` → `buildCreatePayloadFromRow`) брал `comment_text` без обогащения — отсюда «вчера было, сегодня нет».
- Красная рамка блока оплаты: `highlight` включался от сохранённого внимания `new/changed` на квитанции (`isHighlighted(fee)`) и на самом чеке — собственная загрузка чека клиентом не снималась с «new/changed» и не попадала в seen-базу.
- `docsAction` («Требуются подписи/документы») ставился любым push, пока подстатус `primary_documents_sent`/`signature_revision_required` — без проверки, есть ли реально незагруженные `*_sign`; снимался только внутри деталки.
- Текст формы «Пояснение» («В собственности автомобиль …») генерирует 1С — локального генератора в сервере/МП/админке нет; год добавлен в наш комментарий `Авто в собственности: <name>, <year>`.
- Статусы в МП приходят только через FCM-push (notification+data), пуллинга нет, WebSocket — только чат. Сервер шлёт push без `android.priority` → normal; на iOS FCM→APNs идёт сразу — вероятная причина разницы Android/iPhone (Doze-батчинг — гипотеза интервала, механизм подтверждён кодом).
- `individualInn`/`individualPhone` в цепочке не теряются: МП шлёт в create → сервер пишет `individual_inn`/`individual_phone` → `SELECT *` → оба билдера мапят в payload 1С. Прод-запись id=70 подтверждает.

## Сделано

- Сервер: `buildCreatePayloadFromRow` тоже обогащает `commentText` (через `questionnaireFromRow`); обогащение идемпотентно — «Повторный ввоз» и «Авто в собственности:» не дублируются, если уже есть в тексте; в `Авто в собственности:` выводится год из `ownedVehicles[].year`.
- МП: пустой слот подписи — i18n `requestFileUploadHint` («Загрузить»/«上传») вместо «Требуется подпись».
- МП: `requestStatusActionHint` — `originals_complete_*` → `null` (нет напоминания про оригиналы при полной сдаче).
- МП: красная рамка блока оплаты — только пока нет чека (либо чек сам «new/changed»); собственная загрузка чека/подписи снимается с «new/changed» и пишется в seen-базу (`markUploadedDocSeen`); секция «Финансы» гасит внимание при открытии, как остальные секции.
- МП: `markDocsAction` по push — только когда реально есть незагруженные клиентом файлы (`hasPendingClientUploadActions`); после успешной загрузки `*_sign` бейдж снимается сразу.
- Доки: `api-1c.md`, `api.html` — `commentText` обогащается на всех путях; `request-lifecycle.md`; инварианты в `pitfalls-and-regression-guards.md`.
